# Security Policy

## Поддерживаемые версии

Исправления безопасности выпускаются только для последней мажорной версии
(строка `latest` на npm и Docker Hub).

## Как сообщить об уязвимости

**Не открывайте публичный issue с деталями уязвимости.**

Предпочтительный способ — приватный отчёт через GitHub:
[Security → Report a vulnerability](https://github.com/VadimOnix/kaiten-mcp-server/security/advisories/new).

Если форма недоступна, откройте issue с пометкой «security» **без технических
деталей** и способом связаться с вами — детали передадим приватно.

Ответ — в течение 7 дней. Исправления публикуются автоматическим релизом
(npm + Docker Hub) сразу после подтверждения и фикса.

## Замечания по эксплуатации

- `KAITEN_API_TOKEN` передавайте только через переменные окружения; сервер
  автоматически редактирует токены в логах и ошибках.
- Docker-образ запускается от непривилегированного пользователя и не открывает
  сетевых портов (MCP stdio).
- `KAITEN_INSECURE_SSL=true` отключает проверку сертификатов — используйте
  только в доверенных сетях.

## Известные предупреждения `npm audit`

`npm audit` показывает 7 уязвимостей в dev-зависимостях. **Их нельзя починить из
этого репозитория, и они не попадают к пользователям.** Проверка, которая
отражает реальность, — только по production-дереву; она же стоит в CI и в
релизном пайплайне:

```bash
npm audit --omit=dev   # found 0 vulnerabilities
```

Все 7 живут внутри `node_modules/npm/node_modules/*` — это CLI `npm`, который
`@semantic-release/npm` тянет как зависимость, чтобы выполнять `npm publish`.
Затронуты `brace-expansion`, `ip-address`, `undici` и `tar`.

Почему ничего нельзя сделать:

- **`overrides` не работают.** `npm` публикует эти пакеты как
  `bundleDependencies` — 65 штук внутри собственного тарбола. Проверено: указание
  исправленных версий в `overrides` не меняет содержимое бандла, npm лишь
  переносит свою копию глубже по дереву.
- **Свежий `npm` не помогает.** Последний на сегодня `npm@12.0.2` везёт тот же
  уязвимый набор, что и текущий `npm@11.19.0`. Апгрейд проверен — те же 7.
- **Предлагаемый `npm audit fix --force` делает хуже.** Он откатывает
  `semantic-release` 25 → 24.2.9, а это `@semantic-release/npm@12` →
  **`npm@10.9.3`**, то есть версия CLI *старше* нынешней. Аудит замолкает не
  потому, что код исправлен, а потому, что старые версии не попадают в диапазоны
  текущих advisory.

Ждём, пока npm опубликует релиз с обновлённым бандлом. До тех пор красный
`npm audit` без `--omit=dev` — ожидаемое состояние, а не регрессия.
